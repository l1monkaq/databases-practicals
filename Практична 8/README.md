# Практична робота №8. Створення структури бази та її об’єктів (SQL DDL)

**Предмет:** Бази даних  | **Група:** ІПЗ-41  | **Виконала:** Єва Якимчук

## Перелік файлів
- `schema.sql` — повна реляційна схема бібліотеки з практичної №4 (`library.books`, `copies`, `readers`, `employees`, `loans`).
- `alter.sql` — окремі зміни `college.courses`, приклад `TRUNCATE` та `DROP`, обробка помилки залежності.

**Порядок:** після практичної №5 створити базу `college`, виконати `practice-07/schema.sql`, `practice-08/schema.sql`, `practice-08/alter.sql`. Кожен `schema.sql` призначений для своєї схеми (`college` та `library`). УВАГА: початкові `DROP TABLE` видаляють попередні навчальні дані; запускати лише на тестовій базі.

## Результати, які очікуються після виконання
| Крок | Результат |
|---|---|
| ALTER ADD | у `college.courses` є `description` |
| ALTER DEFAULT | нові рядки отримують текст за замовчуванням, якщо поле пропущено |
| ALTER DROP | колонка `description` зникає |
| TRUNCATE | лічильник рядків змінюється з 2 на 0, таблиця існує |
| DROP | таблиця `ddl_demo` зникає із `information_schema` |
| DROP departments | PostgreSQL відхиляє видалення через FK `courses.department_id` |

**Пояснення помилки:** `DROP TABLE college.departments` не виконується, доки `college.courses` має зовнішній ключ на цю таблицю. Код перехоплює `dependent_objects_still_exist` і друкує NOTICE замість переривання всього файлу. `CASCADE` видалив би залежні об'єкти та є ризиковим.

## Ризики
`DROP TABLE`, `DROP COLUMN` видаляють дані; `TRUNCATE` швидко видаляє всі рядки; `ALTER ... TYPE` може потребувати перетворення та втратити точність; `ALTER SET NOT NULL` може не спрацювати для старих NULL. Безпечніше робити резервну копію, перевіряти міграцію на копії та застосовувати транзакцію.

## Питання для захисту
1. TRUNCATE видаляє всі рядки без WHERE, DELETE може видаляти вибрані рядки з WHERE.
2. Backup → тестове середовище → міграція у транзакції → перевірка → застосування.
3. Щоб не залишилися «висячі» залежні ключі/об'єкти.
4. DROP COLUMN, скорочення типу, перетворення типу, небезпечна зміна DEFAULT/NOT NULL.


## Висновок
Складено повний DDL для бібліотеки і окремий навчальний скрипт зміни структури. Очікувані ефекти описані; реальний запуск PostgreSQL залишається виконати.
