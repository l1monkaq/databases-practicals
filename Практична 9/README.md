# Практична робота №9. Маніпулювання даними у SQL/DML

**Предмет:** Бази даних  | **Група:** ІПЗ-41  | **Виконала:** Єва Якимчук

## Запуск
Потрібна порожня схема після `practice-07/schema.sql`. Виконати файл `dml.sql` один раз у PostgreSQL, бажано через `psql -v ON_ERROR_STOP=1 -d college -f dml.sql`. Скрипт містить транзакцію, `INSERT`, `RETURNING`, `UPDATE ... WHERE`, `DELETE ... WHERE` і 5 `SELECT` із псевдонімами, розрахунками та сортуванням.

## Результати до та після (очікувані, не знімок із СКБД)
**UPDATE:**
| Крок | student_id | course_id | status | grade |
|---|---:|---:|---|---|
| до | 101 | 1 | active | NULL |
| після | 101 | 1 | completed | 92 |

Другий запис студента 101 на курс 2 залишається `active`. **DELETE:** до — рядок `(104,2,'cancelled')`, після — немає записів; сам студент 104 і курс 2 залишаються, бо видалено лише зв'язок.

## П'ять запитів SELECT
1. Перелік студентів за `student_id` (4 рядки).
2. Курси та розрахунок `credits*30`: DB 120, WEB 90, PHY 150 год; упорядковано за кредитами від більшого до меншого.
3. Список підрозділів за кодом: FIZ, IT.
4. Реєстрації після змін: 4 рядки; `(101,1)` завершено з 92 балами.
5. Плата після умовного підвищення на 10%: DB 1320.00, WEB 1210.00, PHY 1045.00; це **обчислення SELECT**, ціни в таблиці не змінюються.

## Чому WHERE обов'язковий
`UPDATE` без WHERE змінить усі рядки, а `DELETE` без WHERE видалить усі рядки таблиці. Тут `WHERE student_id=101 AND course_id=1` та `WHERE student_id=104 AND course_id=2` точно вказують на один запис за складеним ключем. Видалення реєстрації не видаляє її батьківські таблиці.

## Питання для захисту
1. UPDATE без WHERE оновить усі рядки.
2. RETURNING одразу повертає значення вставлених/змінених/видалених рядків.
3. ON DELETE для FK визначає поведінку при видаленні **батьківського** запису.
4. VALUES додає явні рядки, INSERT SELECT додає результати вибірки.
