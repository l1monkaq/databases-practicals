# Практична робота №5. Первинне налаштування СКБД і створення навчальної бази

**Дисципліна:** Бази даних  
**Група:** ІПЗ-41  
**Виконала:** Єва Якимчук

## Мета
Встановити та перевірити PostgreSQL, створити навчальну базу даних і схему, перевірити з'єднання та зберегти фактичні результати.

## 1. Середовище

- Операційна система: Windows (зі скриншотів pgAdmin).
- Сервер СКБД: **PostgreSQL 18.6**, що підтверджує результат запиту `SELECT version()`.
- Клієнт: **pgAdmin 4**; номер версії pgAdmin не перевірявся.
- Локальний сервер у pgAdmin: **PostgreSQL 18**.
- База: **`college`**.
- Схема: **`college`**.
- Користувач під час показаної перевірки: **`postgres`**.
- Порт для локального підключення під час інсталяції: 5432 (значення видно на попередньому екрані Stack Builder; у SQL-сесії порт окремим запитом не перевірявся).

**Безпека:** пароль не включено до звіту, коду чи скриншотів.

## 2. Фактично виконані дії

1. Встановлено PostgreSQL 18 і запущено pgAdmin 4.
2. Під'єднано локальний сервер `PostgreSQL 18`.
3. Створено базу даних `college` через меню `Databases → Create → Database`.
4. У базі `college` створено схему з назвою `college` через `Schemas → Create → Schema`.
5. У Query Tool виконано перевірку версії PostgreSQL, назви поточної бази та поточного користувача.
6. Збережено три **реальні** скриншоти цих результатів.

## 3. Коректні SQL-запити для перевірки

```sql
SELECT
    version() AS postgres_version,
    current_database() AS database_name,
    current_user AS username;

SELECT
    current_database() AS database_name,
    current_user AS username;

SELECT schema_name
FROM information_schema.schemata
WHERE schema_name = 'college';
```

> У PostgreSQL `current_user` — спеціальний вираз, тому правильно **`current_user`**, а не `current_user()`; останній варіант спричиняє синтаксичну помилку. `version()` та `current_database()` використовуються з дужками.

Додатково цей код збережено у файлі [`verification.sql`](verification.sql).

## 5. Що ще потрібно перевірити для повного виконання практичної

- Створення та підключення окремої навчальної ролі **`college_student`**, якщо цього вимагає завдання. Зараз знімки показують роботу від `postgres`, а не від `college_student`.
- Підключення та тестові SQL-команди через **`psql`** — реальних знімків термінала поки немає.
- Окремий запуск `SELECT schema_name ...` — схема видна в дереві pgAdmin, але результат саме цього SQL-запиту на наданих скриншотах ще не показаний.
- За необхідності — підключення через DBeaver. Воно не показане.

Підготовчий файл [`setup.sql`](setup.sql) містить шаблон для створення ролі. Він **не підтверджує**, що цю роль уже створено. У GitHub не завантажувати справжні паролі.

## 6. Контрольні запитання

1. **Що таке роль у PostgreSQL?** Роль — обліковий об'єкт, якому можна призначати права; роль із атрибутом `LOGIN` може входити на сервер.
2. **Чим база відрізняється від схеми?** База даних — окремий контейнер даних, а схема організовує об'єкти всередині певної бази даних.
3. **Як підключитися з термінала?** Наприклад: `psql -h localhost -p 5432 -U postgres -d college` (з локальним паролем).
4. **Навіщо потрібне UTF-8?** Кодування дозволяє зберігати Unicode-текст, у тому числі українські символи.

## Висновок

Під час роботи було встановлено PostgreSQL та успішно відкрито локальний сервер у pgAdmin 4. Створено базу даних `college` й однойменну схему. SQL-перевірка підтвердила, що використовується PostgreSQL 18.6, поточна база — `college`, а користувач — `postgres`. Результати задокументовано трьома фактичними скриншотами. У процесі виправлено синтаксис запиту до `current_user`. Для повного завершення налаштування навчального користувача та перевірки консольного підключення залишилися окремі кроки, які не вважаються виконаними без підтвердження.
