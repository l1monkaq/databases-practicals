## 3. Аналіз запитів та порівняння результатів

### 3.1. INNER JOIN (Внутрішнє з'єднання)
```sql
SELECT d.name AS department, c.title AS course
FROM college.courses AS c
JOIN college.departments AS d USING (department_id)
ORDER BY d.name, c.title;
```
* **Очікуваний результат (4 рядки):**

| department | course |
|---|---|
| Інформаційні технології | Бази даних |
| Інформаційні технології | Вебтехнології |
| Фізика | Астрономія |
| Фізика | Загальна фізика |

* **Аналіз зниклих рядків:**
  * Зник підрозділ **«Гуманітарні науки»**, тому що в таблиці `courses` немає жодного запису з `department_id = 3`.
  * Зник курс **«Міжкафедральний семінар»**, оскільки його `department_id` є `NULL` (умова з'єднання `NULL = department_id` повертає `UNKNOWN`, що відкидається `INNER JOIN`).

---

### 3.2. LEFT JOIN (Ліве зовнішнє з'єднання від кафедр до курсів)
```sql
SELECT d.name AS department, c.title AS course
FROM college.departments AS d
LEFT JOIN college.courses AS c USING (department_id)
ORDER BY d.name, c.title;
```
* **Очікуваний результат (5 рядків):**

| department | course |
|---|---|
| Гуманітарні науки | *NULL* |
| Інформаційні технології | Бази даних |
| Інформаційні технології | Вебтехнології |
| Фізика | Астрономія |
| Фізика | Загальна фізика |

* **Пояснення рядків із NULL:** До вибірки включено кафедру «Гуманітарні науки». Оскільки для неї немає відповідних курсів, усі стовпці правої таблиці (`c.title`) автоматично заповнюються значенням `NULL`. Курс «Міжкафедральний семінар» сюди не потрапляє, бо його немає у лівій таблиці `departments`.

---

### 3.3. RIGHT JOIN та FULL JOIN

#### RIGHT JOIN (від кафедр до курсів)
```sql
SELECT d.name AS department, c.title AS course
FROM college.departments AS d
RIGHT JOIN college.courses AS c USING (department_id)
ORDER BY d.name NULLS LAST, c.title;
```
* **Очікуваний результат (5 рядків):**
  * Включає 4 стандартні курси + рядок:
    `department = NULL | course = 'Міжкафедральний семінар'`.
  * **Порівняння з LEFT JOIN:** зникла кафедра «Гуманітарні науки» (бо вона ліва і не має курсів), натомість додався безкафедральний курс (бо він правий).

#### FULL JOIN (Повне зовнішнє з'єднання)
```sql
SELECT d.name AS department, c.title AS course
FROM college.departments AS d
FULL JOIN college.courses AS c USING (department_id)
ORDER BY d.name NULLS LAST, c.title;
```
* **Очікуваний результат (6 рядків):**

| department | course | Примітка |
|---|---|---|
| Інформаційні технології | Бази даних | Повний збіг |
| Інформаційні технології | Вебтехнології | Повний збіг |
| Фізика | Астрономія | Повний збіг |
| Фізика | Загальна фізика | Повний збіг |
| Гуманітарні науки | *NULL* | Збережено ліву кафедру (додано з LEFT) |
| *NULL* | Міжкафедральний семінар | Збережено правий курс (додано з RIGHT) |

---

### 3.4. Звіт «Студент — Курс — Оцінка» з двома послідовними JOIN
```sql
SELECT s.student_id,
       s.full_name AS student_name,
       COALESCE(c.title, '(немає реєстрацій)') AS course_title,
       e.status,
       COALESCE(e.grade::TEXT, '—') AS grade
FROM college.students s
LEFT JOIN college.enrollments e ON s.student_id = e.student_id
LEFT JOIN college.courses c ON e.course_id = c.course_id
ORDER BY s.student_id, c.title;
```
* **Результат:** 6 рядків. Студент Бондаренко Денис (який не обрав жодного курсу) присутній у звіті із позначкою `(немає реєстрацій)`, що критично важливо для повноти академічної звітності.

---

### 3.5. Відмінність між `USING` та `ON`

| Критерій | Предикат `USING (col)` | Предикат `ON left.col = right.col` |
|---|---|---|
| **Вимога до назв** | Стовпці в обох таблицях повинні мати **абсолютно однакову назву** (`department_id`). | Стовпці можуть мати різні назви (`d.id = c.dep_id`). |
| **Поведінка при `SELECT *`** | Стовпець об'єднання виводиться **лише один раз** (як спільне коалесковане значення). | Обидва однойменні стовпці дублюються у вибірці окремо: `d.department_id` та `c.department_id`. |
| **Складні умови** | Дозволяє лише просту перевірку на рівність одного чи кількох полів. | Дозволяє довільні предикати: нерівності (`<`, `>`), поєднання через `AND`/`OR`, виклики функцій. |

## 4. Відповіді на питання для захисту

1. **Що повертає `LEFT JOIN`, якщо для лівого рядка немає пари?**
   `LEFT JOIN` зберігає рядок лівої таблиці в повному обсязі, а для всіх полів правої таблиці, які не знайшли відповідності за умовою з'єднання, генерує псевдозначення `NULL`.

2. **Чим `INNER JOIN` відрізняється від `LEFT JOIN`?**
   `INNER JOIN` повертає виключно ті рядки, для яких умова з'єднання виконується (результат перевірки `TRUE`). Якщо рядок з лівої або правої таблиці не має пари, він відкидається. `LEFT JOIN` повертає всі рядки `INNER JOIN` плюс усі незбіжні рядки з лівої таблиці, розширені значеннями `NULL`.

3. **Коли доцільний `FULL JOIN`?**
   `FULL JOIN` використовується для звірки або аудиту двох списків (Reconciliation / Diff), коли потрібно в одному наборі даних побачити:
   * елементи, що присутні в обох таблицях;
   * елементи, наявні лише в першій таблиці (розбіжності зліва);
   * елементи, наявні лише в другій таблиці (розбіжності справа).
   Наприклад, звірка клієнтської бази CRM із базою виставлених рахунків у білінгу.

4. **Як запобігти помилковому множенню рядків при JOIN?**
   Помилкове множення (Fan-out / Картезіанський сплеск) виникає, коли таблиця зв'язується з іншою таблицею, в якій за ключем з'єднання існує кілька записів (зв'язок $1:N$ або $M:N$), а потім приєднується ще одна таблиця $1:M$. Запобігти цьому можна:
   * З'єднанням таблиць суворо за унікальними/первинними ключами.
   * Попереднім агрегуванням дочірньої таблиці в підзапиті (Derived Table / CTE) до виконання JOIN.
   * Використанням `COUNT(DISTINCT column)` замість звичайного `COUNT(*)`.
